# 28

Q: Que fait console.error("Erreur simulée") ? [cours]
+ Il affiche un message classé « erreur », sans lancer d'exception
- Il lance une exception qui interrompt immédiatement le script en cours
- Il arrête le script puis recharge la page automatiquement ensuite
- Il écrit le message dans le fichier de journal du navigateur Web
? log, warn et error classent les messages par gravité dans la console ; ils ne lancent pas eux-mêmes d'exception (c'est le rôle de throw).

Q: À quoi sert console.table(stock) quand stock est un tableau d'objets ? [cours]
+ À présenter les objets en colonnes pour contrôler des données
- À créer un tableau HTML visible dans la page affichée
- À trier les objets selon leur première propriété
- À convertir le tableau d'objets en texte JSON
? console.table affiche un tableau d'objets sous forme de colonnes dans la console, très pratique pour vérifier des données ; ce n'est pas un élément de la page.

Q: Que faut-il respecter entre console.time("inventaire") et console.timeEnd("inventaire") ? [cours]
+ Le même libellé : il identifie le chronomètre à arrêter
- Le même nombre d'appels à console.log entre les deux lignes
- Un délai minimal d'une seconde entre les deux appels
- Le même fichier de script pour les deux appels
? time(label) démarre un chronomètre identifié par son libellé ; timeEnd(label) affiche la durée écoulée et le termine. Les mesures sont indicatives et dépendent du navigateur.

Q: Que fait console.timeLog("inventaire") ? [cours]
+ Il affiche une mesure intermédiaire sans arrêter le chronomètre
- Il arrête le chronomètre et affiche la durée écoulée
- Il remet le chronomètre à zéro et le redémarre aussitôt
- Il enregistre la durée dans le stockage local du navigateur
? timeLog affiche le temps écoulé tout en laissant le chronomètre courir ; timeEnd l'affiche puis le termine.

Q: Que fait console.clear() ? [cours]
+ Il vide l'affichage de la console, sans réparer le bug ni effacer des données
- Il efface les données enregistrées dans localStorage par l'application
- Il supprime du code source l'instruction qui provoque l'erreur
- Il recharge la page pour repartir d'un état propre à chaque appel
? Nettoyer l'affichage ne répare rien. Pour chercher la cause : lire la première erreur, retrouver le fichier et la ligne, isoler l'expression, retester. La console n'est pas un stockage.

Q: Pourquoi un simple console.log n'est-il pas un test fonctionnel complet ? [cours]
+ Il affiche une valeur sans la comparer au résultat attendu
- Il n'affiche que des chaînes de caractères, jamais des nombres entiers
- Il ralentit toujours l'exécution du script de façon bien visible
- Il ne fonctionne que dans les navigateurs récents sur ordinateur
? Un test compare un résultat obtenu à un résultat attendu, sur un cas nominal, une limite et une entrée incorrecte. Afficher une valeur n'en vérifie rien.

Q: Pourquoi une variable JavaScript ne suffit-elle pas à conserver un inventaire ? [cours]
+ Le script est recréé à chaque chargement : la variable repart de zéro
- Une variable ne peut contenir qu'un seul produit à la fois
- Les variables sont envoyées au serveur puis supprimées aussitôt
- Un navigateur n'autorise que dix variables par script chargé
? let total = 3 n'existe que dans le contexte d'exécution ; un nouveau chargement recrée le script. D'où Web Storage pour de petites données, ou une base de données côté serveur.

Q: Quel mécanisme conserve des données après la fermeture de l'onglet, en principe ? [cours]
+ localStorage
- sessionStorage
- Une variable JavaScript
- La console du navigateur
? Une variable disparaît au rechargement ; sessionStorage dure autant que la session de l'onglet ; localStorage persiste entre les visites. Aucun stockage navigateur ne garantit une conservation permanente : l'utilisateur peut l'effacer.

Q: Quelle est la portée de sessionStorage ? [cours]
+ Une session de page : séparée par onglet et par origine
- Tous les onglets du navigateur, pour toutes les origines
- Tous les onglets d'une même origine, comme localStorage
- Le seul fichier script.js qui a écrit la valeur
? Il survit au rechargement du document mais reste lié à l'onglet : fermer l'onglet termine en principe la session. Un nouvel onglet indépendant ne partage généralement pas la valeur.

Q: Quelles pages partagent le localStorage de http://localhost:8080/index.html ? [cours]
+ http://localhost:8080/autre.html
+ http://localhost:8080/dossier/page.html
- http://localhost:3000/index.html
- https://localhost:8080/index.html
? L'origine = protocole + nom d'hôte + port. Le stockage est attaché à une origine, pas à un dossier ni à un fichier JavaScript.

Q: Que vaut typeof localStorage.getItem("quantite") après localStorage.setItem("quantite", 12) ? [cours]
+ "string" : Web Storage ne conserve que des chaînes
- "number" : le type d'origine est conservé par le navigateur
- "object" : la valeur est enveloppée dans un objet Storage
- "undefined" : getItem ne renvoie que des clés de stockage
? setItem convertit la valeur en chaîne : 12 devient "12". À la lecture, Number() redonne un nombre, à valider avant tout calcul.

Q: Que renvoie localStorage.getItem("cle-inconnue") ? [cours]
+ null
- undefined
- Une chaîne vide
- Une exception de type KeyError
? getItem renvoie une chaîne, ou null si la clé est absente. Attention : Number(null) vaut 0, donc on vérifie brut !== null avant de convertir.

Q: Pourquoi vérifier brut !== null avant Number(brut) pour une valeur lue dans localStorage ? [cours]
+ Number(null) vaut 0 : une clé absente passerait pour une quantité de zéro
- Number(null) lève une TypeError qui arrêterait le script en cours
- getItem renvoie parfois un tableau qu'il faut d'abord aplatir
- Number() refuse toute valeur provenant d'un stockage du navigateur
? Une clé absente donne null ; sans le test, une quantité inexistante serait confondue avec une quantité nulle.

Q: Pourquoi servir les exercices depuis http://localhost plutôt que d'ouvrir le fichier avec file:// ? [cours]
+ Une origine HTTP stable évite les comportements particuliers de file://
- Le navigateur refuse d'exécuter un script ouvert depuis le disque
- localStorage n'existe que pour les pages servies en HTTPS
- Les DevTools sont désactivés pour les fichiers ouverts localement
? Avec file://, le comportement de Web Storage peut être limité ou varier. On sert la page avec un petit serveur local (python -m http.server, Live Server…) et on inspecte l'onglet Application/Stockage. Ce serveur sert aux essais locaux, pas à la production.

Q: Pourquoi ne jamais stocker un mot de passe ou un jeton sensible dans localStorage ? [cours]
+ Tout JavaScript de la même origine peut le lire, et l'utilisateur peut le modifier
- Le navigateur chiffre automatiquement les valeurs, qui deviennent inutilisables
- localStorage est effacé à chaque rechargement, ce qui perdrait la valeur
- Les valeurs sont envoyées au serveur à chaque requête, de façon visible
? Web Storage n'a ni contrôle d'accès métier ni confidentialité : un script de la même origine (par exemple injecté par XSS) peut tout lire. Pas de données sensibles dans un exercice, et encore moins de données de santé.

Q: Que supprime localStorage.clear() ? [cours]
+ Toutes les clés de l'origine, y compris celles d'autres usages
- Seulement les clés créées par le script qui l'appelle
- Seulement les clés dont la valeur est une chaîne vide
- Uniquement les données de l'onglet courant
? clear() efface toutes les clés de cette origine : prudence. Pour une seule donnée, on utilise removeItem("cle").

Q: Quelles affirmations sur Web Storage sont vraies ? [cours]
+ Il n'est pas synchronisé automatiquement entre deux appareils
+ L'utilisateur peut consulter et modifier ses données avec les DevTools
- Il convient pour stocker des informations de patients, car il est local
- Il garantit une conservation permanente des données écrites
? Mode privé, effacement manuel, quotas et politiques du navigateur peuvent rendre les données indisponibles. Pour un vrai logiciel : serveur, authentification, droits, journalisation et base de données.

Q: Quand les instructions d'une fonction s'exécutent-elles ? [cours]
|function saluer() {
|    console.log("Bonjour !");
|}
+ À chaque appel, avec les parenthèses : saluer()
- Dès la déclaration, au chargement du script
- Une seule fois, au premier appel seulement
- Quand le navigateur est inactif, en arrière-plan
? Déclarer une fonction ne l'exécute pas ; les parenthèses déclenchent l'exécution, autant de fois qu'on le veut. Une fonction a une responsabilité identifiable et un nom qui exprime une action.

Q: Dans cet extrait, que sont nom et quantite d'une part, "Pansements" et 4 d'autre part ? [cours]
|function afficherProduit(nom, quantite) { ... }
|afficherProduit("Pansements", 4);
+ nom et quantite sont des paramètres ; "Pansements" et 4 sont des arguments
- nom et quantite sont des arguments ; "Pansements" et 4 sont des paramètres
- Ce sont tous des variables globales créées par l'appel de la fonction
- nom et quantite sont des constantes ; "Pansements" et 4 des propriétés
? Paramètre : nom local à la fonction, donné à la définition. Argument : valeur transmise lors de chaque appel.

Q: JavaScript vérifie-t-il le type des paramètres d'une fonction ? [cours]
+ Non : aucun type n'est imposé, le contrôle reste à écrire
- Oui : un paramètre déclaré sans type refuse toute valeur
- Oui : le type est déduit du premier argument transmis
- Non, mais une alerte s'affiche si le type change au second appel
? C'est pourquoi les fonctions de validation (estQuantiteValide, convertirQuantite) contrôlent elles-mêmes ce qu'elles reçoivent.

Q: Que vaut r à la fin de ce code ? [cours]
|function double(x) {
|    console.log(x * 2);
|}
|const r = double(4);
+ undefined : la fonction affiche 8 mais ne renvoie rien
- 8 : console.log renvoie la valeur qu'il affiche
- null : une fonction sans return renvoie null
- NaN : double n'a pas reçu de valeur numérique valide
? Une fonction qui se termine sans return renvoie undefined. console.log n'est pas une alternative à return : afficher produit un effet, retourner transmet une valeur exploitable par l'appelant.

Q: Que renvoie estQuantiteValide("3") ? [cours]
|function estQuantiteValide(quantite) {
|    return Number.isInteger(quantite) && quantite >= 0;
|}
+ false : Number.isInteger ne convertit pas "3"
- true : "3" représente bien un entier positif
- NaN : on ne peut pas comparer une chaîne à zéro
- Une TypeError : la fonction attend un nombre
? La fonction attend une valeur number déjà convertie à l'entrée : avec "3" (chaîne), Number.isInteger renvoie false. On retourne directement la condition, sans if/else redondant.

Q: Que se passe-t-il avec ces deux appels ? [cours]
|const seuilAlerte = 5;
|function stockFaible(quantite) {
|    const resultat = quantite < seuilAlerte;
|    return resultat;
|}
|console.log(stockFaible(3));
|console.log(resultat);
+ Le premier affiche true ; le second lève une ReferenceError
- Les deux affichent true : resultat reste visible après l'appel
- Le premier affiche 3 ; le second affiche undefined
- Le premier lève une ReferenceError : seuilAlerte est inaccessible
? quantite et resultat sont locaux à la fonction. La fonction, elle, peut lire seuilAlerte, déclarée dans un contexte englobant.

Q: Que renvoie afficherStock("Gants", null) ? [cours]
|function afficherStock(nom, quantite = 0) {
|    if (nom.trim() === "") {
|        return "Nom de produit obligatoire";
|    }
|    return `${nom} : ${quantite}`;
|}
+ "Gants : null" : seul undefined active la valeur par défaut
- "Gants : 0" : null déclenche aussi la valeur par défaut
- "Gants : undefined" : la valeur transmise est ignorée
- "Nom de produit obligatoire" : null est considéré comme vide
? Le paramètre par défaut s'applique si l'argument est absent ou undefined. Passer null ne l'active pas : il faut valider séparément les types.

Q: À quoi sert le premier return dans afficherStock lorsque nom est vide ? [cours]
+ À quitter la fonction tout de suite : la suite est ignorée
- À retarder le retour du résultat jusqu'à la fin de la fonction
- À afficher le message dans la console sans quitter la fonction
- À remplacer automatiquement nom par une valeur par défaut
? return termine la fonction immédiatement : c'est un retour anticipé (sortie anticipée), souvent plus lisible qu'un else imbriqué.

Q: Pourquoi if (quantite) est-il un mauvais test pour savoir si un produit existe ? [cours]
+ 0 est falsy : un produit présent mais épuisé serait pris pour absent
- quantite est toujours une chaîne, donc toujours truthy
- if (quantite) ne s'exécute jamais pour un nombre supérieur à 1
- Le test lève une exception quand quantite vaut null
? Les valeurs falsy sont false, 0, -0, 0n, "", null, undefined et NaN. Pour distinguer « stock à zéro » de « produit absent », on compare explicitement : quantite !== null.

Q: recupProduit renvoie 0 pour « Gants » (épuisé) et null pour un article absent. Quelle vérification est correcte ? [cours]
+ quantite !== null
- if (quantite)
- if (!quantite)
- quantite == false
? Le contrat de retour commande la comparaison : quantite !== null distingue 0 (valable) de null (absence). if (quantite) et if (!quantite) confondent 0 et null ; == false confond 0 et false.

Q: Pourquoi les fonctions de calcul ne contiennent-elles ni prompt() ni alert() ? [cours]
+ Elles restent indépendantes de la boîte de dialogue, donc testables
- prompt() est interdit à l'intérieur d'une fonction par le standard
- alert() ralentit toutes les fonctions du même fichier de script
- Une fonction ne peut pas afficher de texte à l'utilisateur
? Le traitement de stock peut rester indépendant de la façon de saisir ou d'afficher : prompt et alert seront remplacés par de vrais champs HTML (DOM) sans toucher à la logique métier.

Q: Que vaut produit.quantite à la fin de ce code ? [cours]
|const produit = { nom: "Pansements", quantite: 12 };
|produit.quantite += 3;
= 15
? const empêche de réaffecter produit, pas de modifier les propriétés de l'objet. Un objet regroupe les propriétés liées à une même entité.

Q: Quelle instruction transforme un tableau d'objets en texte avant de l'enregistrer dans localStorage ? [cours]
+ JSON.stringify(stock)
- JSON.parse(stock)
- String.fromJSON(stock)
- stock.toString("json")
? Sérialiser : objet → texte avec JSON.stringify. Désérialiser : texte → objet avec JSON.parse. Web Storage conserve des chaînes.

Q: Que contient la clé après localStorage.setItem("produit", { nom: "Gants" }) ? [cours]
+ La chaîne "[object Object]" : l'objet a été converti sans JSON
- La chaîne {"nom":"Gants"} : le navigateur sérialise automatiquement
- La valeur undefined : les objets ne sont pas acceptés
- Une TypeError empêche l'écriture de la clé
? Oublier JSON produit souvent "[object Object]", qui n'est pas une structure exploitable. On écrit JSON.stringify(objet) et on relit avec JSON.parse.

Q: Que renvoie JSON.parse(brut ?? "[]") quand la clé est absente, donc brut vaut null ? [cours]
+ Un tableau vide : ?? remplace null par la chaîne "[]"
- null : JSON.parse laisse passer la valeur null
- La chaîne "[]", sans conversion en tableau
- Une SyntaxError, car null n'est pas du JSON
? L'opérateur ?? fournit une valeur par défaut quand la valeur de gauche est null ou undefined. Une valeur présente mais malformée doit, elle, être traitée avec try / catch.

Q: Que se passe-t-il avec JSON.parse("invalide") ? [cours]
+ Une SyntaxError : on entoure la lecture d'un try / catch
- La fonction renvoie null sans rien signaler
- La fonction renvoie la chaîne "invalide" inchangée
- La fonction renvoie NaN, comme Number("invalide")
? Un JSON illisible lève une exception. lireStock() intercepte l'erreur et renvoie null pour signaler « lecture impossible ».

Q: Pourquoi tester Array.isArray(stock) après JSON.parse(brut) ? [cours]
+ Un JSON valide peut contenir autre chose qu'un tableau : objet, nombre, texte
- JSON.parse renvoie toujours une chaîne qu'il faut ensuite convertir
- Un tableau lu depuis le stockage perd sa propriété length
- Array.isArray remplace l'appel à JSON.parse pour les tableaux
? Faire confiance au stockage est une erreur : un JSON valide peut représenter un autre type que celui attendu. On contrôle la structure (et idéalement chaque produit : nom et quantite).

Q: lireStock() renvoie [] ou null. Que signifient ces deux valeurs ? [cours]
+ [] : aucun stock enregistré ; null : lecture impossible, on ne doit pas écraser les données
- [] : lecture impossible ; null : aucun stock enregistré pour le moment
- Les deux signifient « aucun stock » : on peut écrire par-dessus dans les deux cas
- null signifie un stock vide ; [] signifie que la clé a été supprimée
? null indique une erreur à traiter ; [] représente un inventaire réellement vide. Si la lecture initiale échoue, on bloque les modifications pour ne pas écraser un stock devenu illisible.

Q: Pourquoi enregistrerStock() renvoie-t-elle true ou false ? [cours]
+ setItem peut échouer : ne pas afficher « enregistré » à tort
- Pour compter le nombre de produits écrits dans localStorage
- Parce que setItem renvoie toujours un booléen par définition
- Pour verrouiller le stockage pendant que le script s'exécute
? Quota dépassé, accès refusé, mode privé : l'écriture peut lever une exception. La fonction n'annonce true qu'après un setItem réussi ; le script informe l'utilisateur sinon.

Q: Pourquoi nommer la clé « pharmacie.stock.v1 » plutôt que « stock » ? [cours]
+ Un nom explicite et versionné évite de mélanger formats et exercices différents
- Le navigateur impose un point et un numéro de version dans les clés
- Une clé courte est refusée par localStorage en dessous de dix caractères
- Le suffixe v1 active automatiquement la sauvegarde sur le serveur
? Une clé stable, explicite et versionnée documente le format JSON stocké et évite les collisions avec d'autres données de la même origine.

Q: Que peut-on dire de JSON ? [cours]
+ C'est un format d'échange de données : il ne fournit ni stockage ni sécurité
- C'est un mécanisme de stockage intégré aux navigateurs, comme localStorage
- C'est un format qui chiffre les données avant leur enregistrement
- C'est un langage de programmation exécuté par le moteur JavaScript
? JSON décrit comment représenter des données sous forme de texte ; il ne dit rien de l'endroit où on les conserve ni de leur protection.

Q: Dans le cas du pharmacien, que fait ajouterProduit pour un produit déjà présent ? [cours]
+ Il met à jour sa quantité au lieu de créer une ligne identique
- Il ajoute une seconde ligne avec la nouvelle quantité
- Il refuse l'ajout et renvoie false dans tous les cas
- Il additionne les deux quantités sans possibilité de les remplacer
? C'est un choix du cahier des charges de l'exercice (« règle de doublon »), pas une règle universelle.

Q: Que renvoie findIndex quand aucun produit ne correspond à la condition ? [cours]
|stock.findIndex(produit => produit.nom.toLowerCase() === nom.toLowerCase())
+ -1 : à ne pas confondre avec l'indice 0, qui est valide
- 0 : l'indice du premier élément par défaut
- null : l'absence est toujours matérialisée par null
- undefined, comme pour un indice hors du tableau
? findIndex renvoie le premier indice qui répond à la condition, ou -1. Comparer en minuscules des deux côtés rend la recherche insensible à la casse : « Pansements » et « pansements » désignent le même produit.

Q: Pourquoi comparer le choix du menu à "1" (une chaîne) et non à 1 ? [cours]
+ prompt() renvoie du texte et switch compare strictement
- Les nombres sont interdits comme valeurs d'un case
- "1" est converti automatiquement en nombre par switch
- Un menu ne peut contenir que des choix de type string
? prompt() renvoie "1", "2"… : avec ===, 1 ne correspond pas à "1". Chaque branche du switch appelle une fonction spécialisée : le menu dirige, les fonctions travaillent.

Q: Que fait stock.map(p => ({ ...p })) dans ajouterSansEffet ? [cours]
+ Il crée un nouveau tableau d'objets copiés, sans toucher à l'original
- Il modifie chaque produit du stock directement en mémoire
- Il enregistre immédiatement chaque produit dans localStorage
- Il supprime les produits dont la quantité vaut zéro
? map() et la syntaxe ... créent de nouveaux objets simples (copie superficielle). On n'adopte l'état modifié qu'après une sauvegarde effective : un tableau modifié en mémoire n'est pas une sauvegarde réussie.

Q: Que doit contenir une recette de test reproductible par un autre étudiant ? [cours]
+ Préconditions, action, résultat attendu, résultat obtenu et verdict
- Seulement la liste des fonctions écrites et leur nombre de lignes
- Uniquement les captures d'écran de la page après les tests
- Le code source complet, sans résultat attendu précisé
? On réinitialise d'abord le seul stockage du projet, puis on teste entrées, fonctions et persistance, en traçant pour chaque scénario : attendu, obtenu, conforme / non conforme. Minimum demandé : dix scénarios, dont les cas d'erreur.

Q: Que fait continue dans cette boucle de saisie ? [cours]
|while (true) {
|    const saisie = prompt("Produit (stop pour finir)");
|    if (saisie === null) break;
|    const nom = saisie.trim();

- Il relance le programme depuis la première ligne
? break quitte la boucle (stop ou annulation) ; continue abandonne le tour courant et reprend au suivant : ici, pour une saisie vide.

Q: Que mesure console.timeEnd("saisie-stock") autour d'une boucle de prompt() ? [cours]
+ Le temps écoulé, y compris l'attente des boîtes de dialogue
- Seulement le temps de calcul du processeur dans la boucle
- Le temps de chargement de la page avant l'exécution du script
- Le temps d'envoi des saisies au serveur de l'application
? Le chronomètre court tant qu'il n'est pas arrêté : les boîtes de dialogue bloquantes comptent. Les mesures sont indicatives.
